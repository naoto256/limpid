# Windows package candidate

This directory is the 0.9.0 implementation candidate, not a released support
announcement. Native SCM install/upgrade/uninstall and architecture matrix
validation are required before release. Initial packaging is ZIP + PowerShell;
MSI remains a future option.

Run `install.ps1` from elevated 64-bit PowerShell after extracting the package.
The candidate binaries require the Microsoft Visual C++ runtime for their
architecture (`VCRUNTIME140.dll`). This package does not install that runtime.
Existing sibling directories under ProgramData/limpid are preserved, including
their ACLs. Only config/state/log are managed; an existing parent ACL is left
unchanged. Managed directories are created with protected ACLs. Installation
rejects untrusted writes to managed content and parent grants that allow an
untrusted identity to delete the managed directories or change permissions.
It registers `limpid` using the `NT SERVICE\limpid` virtual account, adds that
identity to Event Log Readers, and protects ProgramData/limpid config/state/log
directories. The service can read configuration and modify state/logs. SYSTEM
and Administrators manage all directories. The installer does not start the
service. Review configuration, run `limpid.exe --check --config <absolute path>`,
then `Start-Service limpid`. It is enabled for subsequent boots.

The ZIP also contains the existing parser/function snippets. Copy the snippets
you need under ProgramData/limpid/config/snippets and use relative includes
from limpid.conf. The installer preserves existing configuration and does not
overwrite customized snippets during upgrades.

Control uses the local `\\.\pipe\limpid-control` endpoint. Run limpidctl elevated.
The exporter also needs an authorized identity; this package does not install
it as an additional service or expose an HTTP listener automatically.

Use `Stop-Service limpid` for graceful shutdown. SCM PARAMCHANGE (control 6)
requests the existing configuration reload operation. Do not use process kill
as proof of a successful service shutdown. Diagnostic logs go to
ProgramData/limpid/log/daemon.log; the sample pipeline writes events.jsonl.
Console mode uses Ctrl-C/Ctrl-Break for shutdown.

For upgrades, explicitly stop the service and rerun install.ps1. Existing
configuration and checkpoint files are preserved. uninstall.ps1 removes the
stopped service registration and Event Log Readers membership while preserving
binaries and all data. It does not recursively delete any directory.

LTP keys are generated with protected ACLs by limpidctl. A key generated by an
administrator must be provisioned for the service identity before use: owner
must be NT SERVICE\limpid and grants must be restricted to that identity,
SYSTEM and Administrators. The daemon refuses broad or reparse-point keys.

Candidate test matrix: Windows 11 x64/ARM64; Windows Server 2022+ x64. Only
actually tested combinations may be advertised as supported. Security and
provider-specific channels can impose additional read permissions; an input
startup failure is fatal and must be resolved explicitly.

Before release, test installation, first start, startup failure, PARAMCHANGE,
STOP with queued events, upgrade, and uninstall on an elevated test machine.
Verify the service stays stopped after initial installation; its account can
read config and write state/logs; an unrelated standard user cannot connect to
the control pipe or read LTP keys; and upgrade/uninstall preserve existing
configuration and bookmarks. Native foreground tests do not establish SCM
behavior. Debug candidate archives are for validation, not release assets.
